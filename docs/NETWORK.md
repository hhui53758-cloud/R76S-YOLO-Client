# 网络切换和认证

## R76S 直连

运行 `windows_client/切换到R76S网络.bat`，允许管理员确认。脚本将物理有线 IPv4 固定为 `192.168.137.1/24`、移除该接口的网关路由并重置 DNS。R76S 应配置为 `192.168.137.47/24`。Wi-Fi 继续用于上网。

## 恢复学校、酒店或家用网线

保持 Wi-Fi 开启，接上普通网线，运行 `恢复普通网线自动获取IP.bat`。
DHCP（Dynamic Host Configuration Protocol，动态主机配置协议）会自动分配有线地址、网关和 DNS（Domain Name System，域名系统）。若先运行再换线，脚本最多等待约两分钟。

脚本把 Wi-Fi IPv4 优先级设为 25，有线设为 70，数值越小优先级越高。
校园网认证前，即使有线显示连接，也未必可访问互联网。Windows 不会仅凭网页打不开就可靠切换到 Wi-Fi，所以认证期间明确让 Wi-Fi 优先。

认证探测请求通过有线源地址与专用主机路由发送，得到重定向后打开实际认证网页。脚本不记录账户或密码，也不自动提交认证。网页登录成功后关闭 Wi-Fi，即可实际通过有线上网；再次打开 Wi-Fi 时将优先使用 Wi-Fi。

脚本结束前会保留认证页面的有线主机路由，方便完成登录；切到 R76S 网络时会清除该接口的网关路由。重启后 ActiveStore 临时路由通常不保留。

脚本不调整 IPv6；目前验证的是 IPv4 网络。多个有线网卡时脚本优先选择已连接的物理网卡，必要时手动核对。认证页跳到第二台认证服务器或使用域名时，可能需要按网络实际情况增加专用路由；不能保证每种校园认证系统自动适配。

## 故障检查

```powershell
ipconfig /all
curl.exe http://www.msftconnecttest.com/connecttest.txt
```

正常联网测试返回 `Microsoft Connect Test`。网页显示 502 时不能直接判断 DHCP 失败，应检查网关、代理和认证重定向。
脚本同目录的 `network_dhcp_last.log` 和 `network_switch_last.log` 是诊断日志，不要上传；日志可能含本地地址与认证 URL。

这套 IPv4 工作流已在一次需网页登录的有线网络中验证：开启有线时 Wi-Fi 仍可上网，认证成功并关闭 Wi-Fi 后，有线独立通过 HTTP 和 DNS 检查。其他网络应按实际情况验证。
